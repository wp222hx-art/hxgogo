# 图谱数据同步 · 0.3.1

图谱工作台与原平台的五个在线来源共用同一 SQLite 数据库中的 draws 表。图谱不维护开奖副本；后台同步成功后，所有图谱分析从这份数据读取。

## 使用

1. 从旧应用的托盘选择“退出并停止后台”，再启动 0.3.1。新版沿用原数据目录、配置与历史记录，启动时自动完成数据库迁移。
2. 打开“图谱工作台”，选择与原平台相同的数据来源。顶部显示最新期号、本地核对状态和上游延迟情况。
3. 图谱每 5 秒检查数据库版本；新增、历史更正、补漏和删除均会触发更新。窗口重新获得焦点、恢复可见或重新联网时会立即核对。
4. “刷新快照”只读取已入库数据；“同步数据”请求后台补取上游。连续点击会合并并受节流和故障退避约束。
5. 编辑条件、输入未提交或正在计算时保留当前界面，显示“数据库有更新”。完成编辑后自动核对，也可使用“应用数据更新”。显式刷新会按当前已保存条件重绘工具。
6. 网络异常时保留最后成功快照并显示错误，恢复后重新读取。上游不能访问或尚未发布开奖时，不会把历史数据标成上游已更新。

11选5、大乐透、足球等本地导入来源仍使用对应的 atlas_records 数据结构。导入提交后，它们也参与同样的版本检查，但没有虚构外部同步接口。

## 一致性机制

- 数据库迁移 0018 为每个来源增加持久版本和触发器。真实插入、更正、删除会更新版本；相同值更新不触发刷新，重启不重置版本，回滚同时撤销版本变化。
- 一次快照由单条 SQL 读取号码、数量、版本及同步元数据，避免先读号码后读版本时混入另一批变化。接口禁止缓存。
- 后台同库同源请求合并，避免旧响应覆盖较新响应。不同来源独立推进，慢来源不会阻塞其他来源。
- 一批上游号码及成功状态在同一事务提交。任何一行或元数据写入失败都回滚，已存在数据保持完整。
- 提供了非法官方号码的记录会被拒绝；仅当官方号码未提供时，才允许沿用哈希推导。空响应或全部无效响应报告失败，保留原记录。
- 失败按指数退避重试；手动强制同步仍遵守每源最短间隔和退避。历史补漏在独立通道按来源公平轮转，成功后同时使原分析缓存失效。
- 图谱监测复核当前可回溯日志。历史更正保留原观察时间并标识修正，不作为新到达预测或重复提醒；无法复核的片段不冒充连续历史。
- 遗漏查询与 K 线保留已应用参数，数据更新后按同一新快照重算。

本地数据写入和读取具有事务一致性；界面通常在下一次 5 秒检查后应用更新。用户正在编辑时会延期，上游网络、发布延迟和离线状态也会影响新数据到达时间，因此不承诺任何时刻都已获得尚未发布或无法访问的外部数据。

## 共用 API

继续沿用 atlas.v1，保留原有字段与接口：

| 接口 | 行为 |
| --- | --- |
| GET /api/atlas/status?source=… | 只读轻量版本、总量、最新期和同步状态 |
| GET /api/atlas/snapshot?source=…&limit=300 | 同一数据库快照中的记录、数量、持久版本、同步状态与质量 |
| POST /api/atlas/sync | sourceId 与可选 force；仅五个在线来源，复用既有同步服务，不启动策略或 AI |
| POST /api/atlas/import | 本地来源校验并原子导入，重复期号整批拒绝 |
| GET /api/atlas/workspace | 读取图谱方案与设置 |
| PUT /api/atlas/workspace | 保存图谱方案与设置 |

共同元数据包括 revision、count、latestPeriod、latestDrawAt、storage、sync 和 quality。sync 提供 supported、lastAttemptAt、lastSuccessAt、nextDueAt、lastError、failStreak、freshness。未来供数适配器应写入其所属规范表，并遵循相同事务与持久版本协议，前端无需另建同步副本。

## 验证

实际 Electron 测试使用独立目录，验证原有页面、图谱各工具、新期自动显示、最新期不变的历史更正、编辑期间 pending、断线保留快照、恢复后自动更新。测试不使用用户真实密钥或付费 AI。测试输出位于 output 下对应 atlas-sync / atlas-portable 测试目录。
